\section{研究目标}

本文的研究目标是构建一套自进化强化学习系统，使交互式智能体在无人工标注条件下满足以下四个目标：

\textbf{目标一：数据自主产生。} 训练数据的获取基于交互生成——模型在与环境的交互（沙箱内工具调用）以及智能体间的协作（提问者追问、观察者取证）中动态产生新的经验与数据，而非依赖真实用户回流或人工采集。除少量初始种子用于冷启动外，后续训练数据由系统在交互过程中持续自主合成。

\textbf{目标二：奖励可信。} 奖励锚定在环境真实状态而非智能体自述，从取证机制上抑制奖励作弊。

\textbf{目标三：评估器与基建自演化。} 系统不仅演化任务与策略，还应将\textbf{评估器}（各智能体的提示词）与\textbf{基建}（工具集、沙箱、执行环境等）纳入自进化对象，为策略更新提供更可靠的奖励信号与更完善的运行环境。

\textbf{目标四：自进化闭环。} 将上述数据产生、奖励评估、策略更新与评估器/基建自演化的过程组织为持续闭环，使系统在预设终止条件下长时间自主运转、无需人工干预，并在坍缩或崩溃时被及时监控与终止。

\section{自进化过程的形式化定义}
\label{sec:formal_convergence}

传统强化学习在固定任务集上采样、打分、更新策略，任务集由外部供给且训练过程中保持不变。本文将其扩展为一个自进化过程：任务本身由系统基于上一轮经验动态生成。本节先以一个作用于系统状态的\textbf{转移算子}给出该过程的整体形式化，下一节再逐阶段展开其内部结构。

\begin{definition}[自进化系统状态与转移算子]
\label{def:evolution_operator}
记第 $t$ 步的系统状态为四元组
\begin{equation}
\sigma_t = (\theta_t,\, s_t,\, Q_t,\, \Phi_t),
\label{eq:sysstate}
\end{equation}
分别为策略参数、沙箱状态、任务集与评估器/基建状态。一个训练步的演化定义为算子 $\mathcal{T}$：
\begin{equation}
\sigma_{t+1} = \mathcal{T}(\sigma_t) =
\big(\underbrace{\text{GRPO}(\theta_t, R_t)}_{\text{策略}},\;
\underbrace{\text{Inherit}(\tau_t)}_{\text{沙箱}},\;
\underbrace{\text{Questioner}(\tau_t, d_t)}_{\text{任务}},\;
\underbrace{\Phi_t \oplus \Delta_{t'}}_{\text{评估器/基建}}\big),
\label{eq:transop}
\end{equation}
其中 $\tau_t\!\sim\!\pi_{\theta_t}(Q_t)$、$d_t=\text{Observer}(\tau_t)$、$R_t=\text{Judge}(d_t;\Phi_t)$，$\Delta_{t'}$ 项仅在触发时非空。自进化过程即状态序列 $\{\sigma_t\}_{t\ge 0}$ 在 $\mathcal{T}$ 反复作用下的轨道。
\end{definition}

传统强化学习是 $\mathcal{T}$ 的退化情形：任务集 $Q$、沙箱 $s$ 与评估器/基建 $\Phi$ 均由外部初始给定、训练全程固定不变，仅策略 $\theta_t$ 随训练演化；本文的自进化则让四个分量同时演化，因而 $\mathcal{T}$ 是一个任务分布随策略移动的非平稳算子。算子 $\mathcal{T}$ 的各分量如何由一个训练步内的采样、取证、评估、再生成具体产生，在下一节按阶段展开。

\section{自进化强化学习过程定义}
\label{sec:evolution_process}

本节把上一节的转移算子 $\mathcal{T}$ 展开为一个训练步内的具体流程。任务与策略的主循环可分解为三个阶段，依次形式化如下。

\subsection{训练步内的主循环}

\textbf{阶段一：采样与取证。} 策略 $\pi_{\theta_t}$ 在沙箱中对任务集 $Q_t$ 执行、产生交互轨迹集 $\tau_t$，观察者对每条轨迹执行前后的沙箱状态作差，得到确定性状态差分 $d_t$：

\begin{equation}
Q_t \xrightarrow{\ \pi_{\theta_t}\ } \tau_t \xrightarrow{\ \text{Observer}\ } d_t
\label{eq:mainloop_sample}
\end{equation}

该阶段刻画“任务如何变成可评估的证据”：$Q_t$ 经当前策略转化为真实的环境交互 $\tau_t$，再由观察者提炼为客观、不可被策略操纵的状态差分 $d_t$，为后续奖励评估提供锚定在环境真实变化上的依据。

\textbf{阶段二：奖励评估与策略更新。} 外部冻结裁判在当前评估器与基建状态 $\Phi_t$ 下依据 $d_t$ 给出奖励 $R_t$，再由 GRPO 据此更新策略参数：

\begin{equation}
d_t \xrightarrow{\ \text{Judge}(\cdot\,;\,\Phi_t)\ } R_t \xrightarrow{\ \text{GRPO}\ } \theta_{t+1}
\label{eq:mainloop_update}
\end{equation}

该阶段刻画“证据如何转化为策略改进”：奖励以状态差分为输入、以 $\Phi_t$ 为评分口径，使奖励信号可验证且抗作弊；GRPO 据组内相对优势更新参数，得到改进后的策略 $\theta_{t+1}$。

\textbf{阶段三：任务再生成。} 提问者基于本轮执行经验与沙箱状态，为下一轮生成新的任务集：

\begin{equation}
(\tau_t,\, d_t) \xrightarrow{\ \text{Questioner}\ } Q_{t+1}
\label{eq:mainloop_regen}
\end{equation}

该阶段是本文区别于传统强化学习的关键：下一轮任务 $Q_{t+1}$ 不再由外部供给，而是由系统依据上一轮的真实执行与环境状态自主再生成，从而让任务随策略能力持续演化、闭环得以自我延续。三阶段首尾相接、由阶段三产出的 $Q_{t+1}$ 回到阶段一，构成任务与策略在训练步间的协同演化，下标 $t$ 逐步递增。

\subsection{评估器与基建的演化支路}

在上述主循环之外，本文进一步将\textbf{评估器与基建}纳入自进化对象。评估器与基建状态 $\Phi_t$（包含各智能体的提示词与工具/沙箱等基建能力）在阶段二中作为裁判的评分口径出现（$R_t = \text{Judge}(d_t\,;\,\Phi_t)$）。与策略、任务每步更新不同，它\textbf{并非每步更新}，其演化由两式刻画。其一，系统持续收集失败案例集 $\mathcal{B}_{t'}$（下标 $t'$ 表示其按独立的低频周期累积，$t' \le t$）；当且仅当满足触发条件（每隔若干训练步或累积到一定数量失败案例）时，由大模型对 $\mathcal{B}_{t'}$ 归因，产出对评估器/基建的增量更新 $\Delta_{t'}$：

\begin{equation}
\mathcal{B}_{t'} \xrightarrow{\ \text{Attribution}\ } \Delta_{t'}
\label{eq:infra_attr}
\end{equation}

其二，该增量作用于当前状态，得到下一步生效的评估器与基建状态：

\begin{equation}
\Phi_{t+1} =
\begin{cases}
\Phi_t \oplus \Delta_{t'}, & \text{触发更新时}\\[2pt]
\Phi_t, & \text{否则}
\end{cases}
\label{eq:infra_update}
\end{equation}

式~\ref{eq:infra_attr} 刻画“失败案例如何转化为改进项”——由大模型综合任务意图、轨迹与环境证据归因，区分根因在模型侧还是基建侧，产出相应的提示词修订或基建扩展 $\Delta_{t'}$；式~\ref{eq:infra_update} 刻画“改进项如何作用于系统”——以 $\oplus$ 表示将增量并入当前配置（提示词增量修订、基建能力补齐），且多数训练步不触发更新（$\Phi_{t+1}=\Phi_t$）。两个下标解耦：$t$ 为\textbf{训练步}计数、每步递增，$t'$ 为\textbf{失败案例累积周期}计数、随触发缓慢递增。

由此，本文的自进化包含两条更新频率不同的支路：一是每步同步演化的\textbf{主循环}（任务 $Q$、策略 $\theta$、沙箱状态 $s$），二是低频触发的\textbf{评估器与基建演化}（$\Phi$）。二者共同将自进化的对象从传统强化学习仅有的“策略”扩展到“任务、策略、评估器、基建”四维，这是本文与传统强化学习的本质区别。四类状态在训练轮次间的传递即构成系统的数据流：其中策略、沙箱、任务三类每步同步更新，其相邻训练步之间的传递关系如图~\ref{fig:state4} 所示；评估器与基建则与训练步解耦、沿 $\Phi_0 \to \Phi_1 \to \Phi_2 \to \cdots$ 低频演进，其与主循环的时间关系如图~\ref{fig:infra_evolve} 所示。

\section{核心问题}

围绕上述过程与形式化，本文需要解决四个核心问题：

\textbf{核心问题一：如何自主产生交互轨迹与下一轮任务？} 这是自进化数据供给的核心。与依赖人工标注数据、人工构建运行环境的传统范式不同，自进化系统需在极少人工介入下自主产生训练数据：一方面借助系统内多智能体的协作（执行者探索、观察者取证、提问者追问）与历史经验持续生成新的交互轨迹与后续任务，另一方面以上一轮沙箱状态为基础、通过状态的跨步继承与演化产生新的运行环境，从而支撑训练闭环的持续运转。

\textbf{核心问题二：如何使奖励锚定环境真实状态？} 人工干预的减少会使训练过程更难约束，也为奖励作弊提供了更大空间——策略可能仅在自述轨迹中谎报完成而裁判无从核实。因此在此场景下抗奖励作弊尤为关键，需要观察者产出确定性的环境状态差分，使裁判据此打分，而非依赖智能体的自我叙述。

\textbf{核心问题三：如何自监控自进化过程？} 自进化系统长时间无人值守地自主运转，一旦出现策略坍缩或训练崩溃而未被及时发现，后续所有训练步都将在无效信号上空转，白白消耗大量计算资源，甚至可能得出错误结果。因此需要实时监控关键指标，并在坍缩或崩溃发生时自动终止训练。

\textbf{核心问题四：如何让评估器与基建随训练自我完善？} 训练中会持续暴露系统性失败，需要一种机制自动收集失败案例，并由大模型判别其根因落在\textbf{模型侧}（策略的规划、工具使用或方案选择失误）还是\textbf{基建侧}（沙箱、工具、执行环境的缺陷），进而分别对评估器提示词进行增量修订、或将缺失的基建能力补齐为可复用技能，避免同类失败反复积累。

\section{系统研究边界}
\label{sec:research_boundary}

一个完整的自进化系统可在算法、模型规模、沙箱形态、评估方式等多个维度上无限扩展，若不加界定，极易使研究范围过度膨胀、实现日趋繁杂，反而模糊本文真正要论证的核心命题。为此，本节明确划定本文的\textbf{研究边界}：在若干维度上采用固定或简化的设定，将研究精力集中于“数据与奖励的自主供给及自进化闭环的自我维持”这一核心问题，而不在与该问题正交的方向上求全。据此，本文作如下界定：

\begin{itemize}
    \item \textbf{基座模型固定。} 基座模型固定为 Qwen3.5-9B\upcite{qwen3}。Qwen3.5-9B 模型规模适中，具备一定的推理能力、工具调用能力与代码执行能力，且在中文与英文的文本任务上均有较好表现，但仍有较大的提升潜力，适用于算法验证和实验。
    \item \textbf{策略优化算法固定。} 实验的策略优化采用标准 GRPO 算法。本文不改进底层 RL 算法、亦不追求算法最优，算法仅作为验证自进化闭环可行性的既定组件。
    \item \textbf{研究范围为纯文本任务。} 本文将研究范围限定为\textbf{纯文本模态}的智能体任务，即任务描述、工具调用、环境反馈与交付物均以文本形式表示，运行于支持文件系统操作与命令执行的代码沙箱（本地或云端）；不涉及图像、音频、GUI 操作、具身控制等多模态交互形态。这一限定是为了快速推进实验，证明系统可行性。可以通过引入相应的状态表示与取证手段来扩展多模态相关能力，这属于正交的工程外延，不改变本文机制的本质。
    \item \textbf{裁判权重冻结。} 本文没有专门为强化学习过程训练一个专门的奖励模型，奖励模型为权重冻结的大模型接口，以服务形式提供，训练过程中其\textbf{模型权重}保持不变，但其打分所用的\textbf{提示词}属于评估器状态 $\Phi_t$，可由失败案例驱动演化。即本文只演化评估器的提示词而不训练裁判本身，避免引入裁判与策略共同训练带来的耦合与不稳定。
    \item \textbf{训练规模服务于验证目的。} 训练步数不设固定值，由稳定性终止判据决定；但为控制实验时间和成本，同时为方便与传统强化学习训练效果对比，本文中验证自进化可闭环执行的强化学习实验步数限制上限为 50 步。规模以验证系统端到端可运行、闭环可自我维持为目标，而非追求模型能力在具体任务上的绝对提升。
\end{itemize}

上述边界并非系统机制上的约束或能力上的局限，而是\textbf{有意的范围控制}：通过在正交维度上固定设定、抑制系统复杂度的无谓膨胀，使本文得以聚焦并清晰地论证自进化机制本身的有效性；这些被固定的维度在系统跑通后均可作为独立的工程或研究方向进一步展开。

\section{本章小结}

本章建立了自进化强化学习的问题模型。首先将传统固定任务集的训练范式扩展为任务动态生成的闭环过程，以系统状态转移算子 $\mathcal{T}$ 给出整体形式化，再按阶段展开为 $Q_t \to \pi_{\theta_t} \to \tau_t \to R_t \to \theta_{t+1} \to Q_{t+1}$ 的主循环，以及由失败案例集 $\mathcal{B}_{t'}$ 驱动的 $\Phi_t \to \Phi_{t+1}$ 评估器与基建演化支路，明确了策略、沙箱、任务、评估器与基建四类状态的传递。最后界定了四个核心问题与研究边界。后续章节围绕这些问题与形式化结论展开方法设计与系统实现。
