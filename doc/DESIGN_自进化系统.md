# 系统设计 — 面向自进化的智能体强化学习系统

> 本文档是开题报告与论文的**唯一事实来源**。描述最终实现的系统设计,不含调试过程。
> 代码已端到端跑通(2 个训练步,各单元成立)。

---

## 0. 一句话定义

系统 = **多智能体采样**(沙箱内 ReAct actor + diff 驱动 observer + 人设驱动 questioner)+ **超生-淘汰-选组**(推理超生 S×8,淘汰烂组,选梯度最优 N×8 训练)+ **跨 step 自进化**(除初始种子外,后续 query 全由系统生成)+ **标准 GRPO 训练**。

---

## 1. 设计目标

让交互式智能体在**无人工标注**条件下自主产生经验、自主获得可信奖励、持续自我进化。三个子目标:

1. **数据自主**:训练数据绝大部分由系统(多智能体)合成,不依赖真实用户回流。
2. **奖励可信**:奖励锚定在环境真实状态差分,而非智能体自述,从机制上抑制奖励作弊。
3. **自进化闭环**:除第一步的初始种子,后续所有训练 query 由系统基于上一轮经验生成。

本文以**系统设计**为主要贡献,采用标准 GRPO 仅为证明整套系统可行,不追算法最优。

---

## 2. 三智能体采样架构

一次采样由三个协同智能体完成:

| 智能体 | 角色 | 输入 | 产出 |
|--------|------|------|------|
| **Actor**(执行者) | 被训练的策略 πθ | seed query | 沙箱内 ReAct 轨迹 + 沙箱状态 |
| **Observer**(观察者) | 客观取证 | 沙箱 before/after 快照 | 确定性状态差分(diff) |
| **Questioner**(提问者) | 模拟用户 | observer 报告 + 人设 + 历史 | 下一轮 query(跨 step 追问) |

### 2.1 Actor

被训练的策略,在**代码沙箱**中以 ReAct 方式多步调用工具(读写文件、执行代码、调用 API)求解任务。每步经推理引擎生成 token + log_prob,产生一条交互轨迹。

### 2.2 Observer

**确定性取证层,不用 LLM**(跨 step 概括时才用 LLM,见 §5)。在 actor 执行前后对沙箱各拍一次快照,作差得到**状态差分**:

- **FS diff**(文件系统):本轮创建/修改/删除的文件,**带内容**;xlsx/docx/pdf 等富格式在沙箱内提取成文本,可核对。
- **SYS diff**(系统状态):本轮安装的包、开启的端口、启动的进程。

这是奖励的 ground truth——不是让模型复读 actor 自述,而是用环境真实变更锚定完成度。

### 2.3 Questioner

人设驱动的模拟用户。跨 step 时,基于上一轮的执行概括 + 当前沙箱状态,生成符合人设的追问,作为下一轮的 seed query。这使训练数据从第二步起全部由系统自主生成。

---

## 3. 超生-淘汰-选组机制

每个训练步的采样-训练解耦设计:

### 3.1 超生(Sample)

推理阶段超生:用 **S 个 seed query**,每个复制 n 份(GRPO 组大小),rollout 产生 **S×n 条轨迹**。第一步 S = 2N(N = 训练组数);后续步 S = R(上一轮存活组数)。

### 3.2 淘汰(Eliminate)

对 S 组取每组最优轨迹的 reward,丢弃**同时满足**以下条件的组:
- 最优 reward 处于全部组的**后 20%**
- 且最优 reward **< 0.3**

同时满足才丢 → 至少保留 80%。残缺组(因 rollout 失败不足 n 条)直接丢弃(GRPO 组内归一化需完整组)。淘汰后剩 **R 组**。

### 3.3 选组(Select)

先计算所有存活组的优势(advantage),再按**组内优势绝对值均值**降序,选梯度最强的 **N 组**(N×n 条)做 GRPO 训练。选组是 advantage-driven:优先训练学习信号最强的组。

### 3.4 训练(Train)

用选中的 N×n 条轨迹做标准 GRPO 更新(组内奖励归一化 + 固定熵正则防策略多样性坍缩)。

**关键**:推理超生 S×n,训练只用 N×n——超生量(S−N)×n 条轨迹提供了淘汰与选组的样本池,但不进梯度更新。

---

## 4. 差分驱动奖励

奖励不取自 actor 自述,由**外部冻结的大模型裁判**依据 observer 的状态差分打分:

- **完成度**:锚定在 FS diff + SYS diff(环境真实变更),actor 自述仅作交叉核对。当"声称写入 12345"而 diff 显示实为 99999,矛盾被直接暴露。
- **多维评分**:完成度、正确性、轨迹质量、安全,乘性聚合,安全为二元门控。
- **空 diff 短路**:本轮无任何环境效果(空 diff)→ 直接返回 0 分,不调用裁判(省掉昂贵的 LLM 往返)。

这是抗奖励作弊的核心:奖励锚定在**环境真实状态**而非智能体叙事,从取证机制上抑制"谎报完成"。

---

## 5. 跨 step 自进化

除第一步的初始种子,后续所有 query 由系统生成。每个训练步完成后:

1. **取存活组最优轨迹**:从 R 组中每组取 reward 最高的轨迹 + 其沙箱状态快照。
2. **Observer LLM 执行概括**:用 LLM 概括上轮最优轨迹的执行情况(做了什么、产出了什么、还差什么),避免直接沿用轨迹导致模型偏移。
3. **沙箱状态继承**:把上轮最优轨迹的 workspace 文件系统快照(tar+base64)恢复到本轮新沙箱——actor 在上轮产出的文件上继续做,**真状态继承**而非仅文本描述。
4. **Questioner 生成新 query**:基于执行概括 + 当前沙箱状态 + 人设,生成下一轮的 seed query。
5. **S = R**:本轮的 seed 数 = 上一轮存活组数,超生量随淘汰动态收缩(如 32→30→27→26)。

**自进化的本质**:系统不依赖固定数据集,而是基于自身经验(上轮最优轨迹 + 沙箱状态)自主产生下一轮训练任务,形成无人工标注的闭环。

---

## 6. 训练终止判据

系统不设固定步数,而是**训练开始崩溃时停止**。监控以下指标,任一触发即停:

- **奖励标准差坍缩**:组内 reward 的 std → 0(策略多样性坍缩,Echo Trap)
- **优势方差坍缩**:advantage 方差 → 0(组内轨迹得分趋同,无梯度信号)
- **pg_loss 异常**:出现 NaN/Inf,或持续增大不收敛
- **ppo_kl 爆炸**:KL 散度超阈值(策略偏离过远)
- **存活组数 R 崩溃**:淘汰后 R 持续下跌到低于 N(超生池耗尽)

## 7. 工程实现

### 7.1 训练框架

基于 verl 0.8.0(V1 架构),标准 GRPO。通过官方注入点接入自定义 rollout 与选组层,不 fork 框架源码:

- **rollout 注入**:`agent_loop_manager_class` 指向自定义 manager,verl 用它替换默认 rollout,`fit()` 零改动。
- **选组层**:自定义 trainer(`agent_rl_sync`)在 `_compute_advantage` 与 `_update_actor` 之间插入 `select_groups`(淘汰 + 选组)。
- **跨 step**:trainer 在 `_update_actor` 后存存活组的最优轨迹 + 沙箱快照,下一步 `_add_batch_to_generate` 用 Questioner 产的新 query 构造 batch。

### 7.2 沙箱后端解耦

`SandboxClient` Protocol = 接口契约,`register_backend`/`make_sandbox` = 按名选择。本地(local,debug)与云端(e2b,生产)为真实现,换厂商零改调用方。

### 7.3 沙箱状态继承

跨 step 的沙箱状态用 tar+base64 传输:
- **存**:沙箱关闭前,`tar czf - . | base64` 把 workspace 打包成 base64 字符串,经 reward_info → 数据通道回流。
- **恢复**:下一步新沙箱创建后,`base64 -d | tar xzf` 解包注入,actor 在上轮文件上继续。

### 7.4 推理与训练异步分离

推理(lightllm)与训练(FSDP2)异步:rollout 阶段推理引擎独占 GPU,训练阶段推理让出;权重更新后异步同步回推理引擎。

- **单元级**:采样、observer 取证、奖励聚合、选组逻辑、跨 step seed 生成均有 CPU 单元测试覆盖(239 passed)。
